# MyBloomberg

한국 투자자의 관점으로 시세·금리·환율·뉴스를 읽는 로컬 시장 데스크입니다. 공개된 균형형 규칙이 중장기 후보와 점수를 계산하고, Codex는 시장 맥락을 설명합니다.

## 현재 구현

Phase 1 UI/UX 보완과 Phase 2 데이터 파이프라인에 더해, 요청에 따라 Phase 3의 Codex 브리핑 생성까지 연결했습니다. Discord 전송과 평일 예약 실행은 후속 범위입니다.

- 반복되는 탭 소개 문구를 줄이고 오버뷰에서 핵심 시세와 분석을 바로 확인합니다.
- 기본 수집 범위는 **112개**입니다: 한국 주식 22개, 미국 주식 30개, ETF 30개, 환율 20개, 지수·금리·원자재·Bitcoin 10개. 별도 관심 종목은 최대 20개이며 기본 목록과 중복되면 한 번만 수집합니다.
- 주식·ETF 탐색에 한국/미국, 주식/ETF, 업종, 관심 종목, 검색·정렬·페이지 이동을 제공합니다.
- 종목 상세에 최대 252개 일별 관측값, 실적 기준일·수집일, 성장률·재무 지표·ETF 비용, 출처와 누락 사유를 표시합니다. 공급자 이력이 부족하면 실제 확보한 값만 보여줍니다.
- 오버뷰에 실제 Codex 시장 해석, 한국 투자자 관점, 환율 영향, 중장기 매수·매도/축소·관찰 후보를 표시합니다. 각 후보는 근거·위험·진입·이탈·판단 무효화 조건과 출처를 포함합니다.
- 연간 재무 3~5개 회계연도(실제 공급자 범위에 따라 주로4개), 동종 기업 비교, 항목별 점수와 기사별 뉴스 가감 근거를 제공합니다. 주식·ETF 전체 82개 평가를 모델별로 탐색합니다. 같은 수집본과 모형 버전이면 후보·점수·동점 순서는 같습니다.
- 브리핑은 실제 수집 후 자동 생성하며 별도 재생성과 Markdown 내려받기를 지원합니다. 아카이브는 해당 수집본의 시세와 분석을 연결합니다.
- 품질·공급자 상태·실패·지연·샘플을 구분하고 실패하면 이전 성공 결과를 보존합니다.

## 실행

Node.js 22 이상, pnpm, PATH에 등록된 RTK가 필요합니다.

```bash
pnpm install
pnpm dev
```

[로컬 데스크](http://127.0.0.1:3000)를 열고 **시장 데이터 수집**을 누릅니다. 데이터 API 키 없이 시작할 수 있습니다. 저장된 자료가 없으면 첫 실행 안내를, **샘플 둘러보기**에서는 가상 자료와 명시적으로 구분된 샘플 브리핑을 제공합니다. 개발·프로덕션 서버는 `127.0.0.1`에 바인딩합니다.

```bash
pnpm collect              # 실제 수집 → 저장 → Codex 브리핑
pnpm collect --no-briefing # 수집만 실행
pnpm collect:sample       # 가상 fixture와 샘플 브리핑 (Codex 호출 없음)
pnpm brief                # 최신 수집본의 브리핑만 생성
pnpm sources:check        # 데이터와 뉴스 공급자 연결 점검
pnpm build
pnpm start                # 프로덕션 실행
```

### Codex 연결

프로젝트에 포함된 `@openai/codex` 실행기를 사용하며 기존 Codex 로그인 세션을 재사용합니다. 시세·뉴스 수집은 로그인 없이도 동작합니다. 브리핑에서 로그인 오류가 나면 프로젝트 실행기로 로그인한 뒤 다시 생성합니다.

```bash
pnpm exec codex login
```

브리핑은 [Codex 비대화형 실행](https://developers.openai.com/codex/noninteractive)과 JSON Schema를 사용합니다. 전역 설정 파일은 수정하지 않고 실행별 설정을 분리해 전역 MCP·훅과의 충돌을 피합니다. 입력 자료만 분석하도록 외부 검색과 셸 도구를 끄고 비어 있는 임시 작업 폴더에서 읽기 전용으로 실행합니다. OpenAI API 키를 사용하지 않으며 **Codex 구독의 사용 한도는 소비합니다.**

기본 모델은 기존 Codex 설정의 모델을 읽거나 CLI 기본값을 사용합니다. 필요한 경우 `.env.local`에서 아래 선택 설정을 지정합니다.

```dotenv
FRED_API_KEY=
MYBLOOMBERG_DATA_DIR=
MYBLOOMBERG_CODEX_MODEL=
MYBLOOMBERG_CODEX_REASONING_EFFORT=medium
MYBLOOMBERG_CODEX_BIN=
```

`MYBLOOMBERG_CODEX_BIN`은 별도 최신 Codex 실행기가 필요한 경우에만 지정합니다. 미설정 시 프로젝트 실행기를 사용합니다. FRED 키가 없으면 미국 재무부 공식 일별 금리를 사용합니다. FRED를 선택한 뒤 실패하면 출처를 바꾸지 않고 이전 값 또는 누락 상태를 표시합니다. 설정은 서버에서만 사용하며 비밀값을 저장소에 올리지 않습니다.

## 분석 기준

- 현재 기준은 **balanced-1.1.0 / 균형형**입니다. 일반 기업은 다년 성장20·수익성20·현금20·안정성20·동종 가격/현금 비교20점, 뉴스 순조정 ±5점입니다. 금융업과 ETF는 별도 기준을 표시합니다. 자세한 수식·누락 처리·뉴스 규칙은 [선정 기준 문서](docs/scoring-methodology.md)에 있습니다.
- 후보는 스냅샷에 저장한 점수·분류로 고정합니다. Codex가 후보를 새로 고르거나 점수를 바꾸지 않습니다. AI 생성이 실패해도 수집본의 고정 평가를 확인할 수 있습니다. 이전 수집본은 당시 모델 버전을 보존합니다.
- 투자 기간은 **수개월 이상 중장기**입니다. 당일 등락 순위를 매매 추천으로 바꾸지 않습니다.
- 성장·밸류에이션·재무 건전성·ETF 비용·분산·금리·환율을 함께 검토합니다. 매수·매도 후보는 해당 시세와 사용 가능한 재무 자료가 있어야 하며 자료가 부족하면 관찰로 제한합니다.
- 매도·축소는 보유 시 재검토 관점입니다. 보유 종목·비중·취득가·위험 성향은 입력되지 않았습니다. 주문을 실행하지 않습니다.
- 근거 식별자, 종목 존재 여부, 후보 자격, 중복·상충 후보와 입력에서 확인되지 않는 수치를 검증합니다. 한 번 교정한 뒤에도 실패하면 이전 성공 브리핑을 유지합니다. 이 검증이 모델 해석의 정확성이나 투자 성과를 보증하지는 않습니다.
- 임의의 목표가·매수가·손절가·미래 수익률을 만들지 않고 다음 실적·성장 지속성·재무 개선 같은 확인 조건을 제시합니다.
- 재무는 공급자 요약 자료이며 최신 공시 전문을 검토한 결과가 아닙니다. 재무 분기와 현재 시세·수집 시각을 구분하고 누락 지표를 0으로 간주하지 않습니다. 지표별 집계 기간(TTM·분기 등)은 다를 수 있으며 최신 분기 날짜가 모든 수치의 집계 기간을 뜻하지 않습니다.
- 가격 이력은 해당 구간 가격 변화이며 배당·환율 수익을 포함한 총수익률이 아닙니다.

## 데이터 소스와 한계

| 소스 | 용도 | 기준 |
|---|---|---|
| Yahoo Finance 호환 데이터 | 시세, 일별 이력, 주식 재무, ETF 비용 | 비공식 어댑터, 누락 가능 |
| 미국 재무부 | 미국 국채 2년·10년 | [공식 일별 XML](https://home.treasury.gov/treasury-daily-interest-rate-xml-feed), 키 불필요 |
| FRED | 선택 미국 금리 공급자 | 개인 API 키 설정 시 사용 |
| GDELT | 글로벌 뉴스 후보 | 최근 24시간, 발견 시각 명시 |
| Federal Reserve·한국은행·SEC RSS | 공식 발표와 정책 뉴스 | 원문 링크 유지 |
| CNBC Finance·Asia RSS | 공개 금융·아시아 뉴스 | 공개 제목·요약과 원문 링크 |

뉴스는 제목·링크·시각·공개 요약만 저장하며 기사 전문은 읽거나 저장하지 않습니다. URL과 유사 제목을 중복 제거하고 출처별·전체 건수를 제한합니다. 새 기사 0건과 공급자 연결 실패를 구분합니다. 뉴스가 부족하면 브리핑의 해석 범위를 표시합니다. GDELT 공유 요청 제한과 공급자별 누락은 소스 상태에 남습니다.

시세는 공급자가 제공한 값이며 실시간 체결을 보장하지 않습니다. 신선도 판정은 거래소 시간대·주말·정규장과 금리 공시 주기를 고려하나 **공휴일·특별 휴장 달력은 자동 반영하지 않습니다.** 일별 금리는 관측일만 표시하고 시각을 만들어 넣지 않습니다. 개별 통화쌍·재무 지표·이력을 가져오지 못하면 해당 항목만 누락 또는 지연으로 표시합니다.

## 저장과 복구

Git에서 제외한 `data/`에 저장합니다. `MYBLOOMBERG_DATA_DIR`로 절대 경로를 지정할 수 있습니다.

```text
data/
├─ snapshots/날짜/식별자.json  # 수정하지 않는 수집 당시 자료
├─ reports/날짜/식별자.json    # 검증된 Codex 또는 샘플 브리핑
├─ reports/날짜/식별자.md      # 동일 브리핑의 Markdown
├─ report-snapshots/          # 수집본별 브리핑 연결
├─ runs/                     # 수집 이력
├─ briefing-runs/            # 분석 실행 이력
└─ config/watchlist.json      # 관심 종목
```

최신 포인터와 실행 상태는 원자적으로 갱신합니다. 실제·샘플 최신 포인터가 분리되어 샘플 값이 실제 수집의 복구값으로 섞이지 않습니다. 동일 PC의 CLI와 UI에서 중복 요청하면 활성 작업을 반환합니다. 최신 화면에서 이전 성공 브리핑을 보여줄 때는 자료 기준이 다름을 표시하며 아카이브에 다른 수집본의 브리핑을 붙이지 않습니다.

## 다음 범위

**다음 우선 목표는 [중장기 선정 기준 백테스트와 성과 검증](docs/backtesting-next-goal.md)입니다.** 당시 공개된 공시·정정 이력과 종목 구성을 재현해 한국·미국 지수 대비 수익률·최대 낙폭을 비교하고, 결과와 판단 근거를 화면에서 확인하도록 개발합니다. 현재는 목표와 완료 기준을 문서화한 단계이며 백테스트 결과나 성과 화면은 아직 구현하지 않았습니다.

현재 Yahoo 재무 이력을 과거에 그대로 대입하지 않습니다. 시점별 자료의 확보 범위부터 점검하고, 벤치마크·검증 기간·리밸런싱·거래비용 가정은 실행 전에 확정합니다. 실제 성과가 낮아도 같은 기준으로 결과를 보존합니다.

Phase 4의 리포트·데스크 상세 경험은 현재 화면에 통합했습니다. Phase 5의 Discord 웹훅 전송과 Windows 작업 스케줄러 예약 실행은 후순위이며 아직 구현하지 않았습니다. 현재는 화면 버튼이나 CLI로 수집·분석합니다. 향후 오전 7시 30분 자동 실행 시에는 PC가 켜져 있어야 합니다.

초기 제품 설계는 [상세 설계 문서](docs/superpowers/specs/2026-08-02-mybloomberg-prototype-design.md)에 남아 있습니다. 구현 현황과 실행 방법은 이 README를 기준으로 합니다.
