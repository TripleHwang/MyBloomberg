## 1. 왜 만들게 되었나

시장 정보는 넘치지만, 매일 아침 실제로 필요한 질문은 단순하다.

- 밤사이 글로벌 시장에서 무엇이 움직였는가?
- 금리·환율·원자재 변화가 한국 시장에 어떤 의미인가?
- 오늘 주목해야 할 뉴스와 일정은 무엇인가?
- 관심 종목에 영향을 줄 만한 조건은 무엇인가?

기존 금융 서비스는 정보량은 많지만 개인의 관점에 맞춘 설명이 부족하다. MyBloomberg는 모든 데이터를 보여주는 제품이 아니라, **내가 아침에 판단을 시작하는 데 필요한 정보와 해석을 한 화면에 정리하는 개인 도구**를 목표로 한다.

## 2. 제품 콘셉트

MyBloomberg의 핵심 경험은 세 단계다.

### Observe — 숫자를 본다

한국·미국 지수, 원/달러, 미국 국채 금리, 금·WTI, Bitcoin, 관심 종목의 움직임을 확인한다.

### Understand — 맥락을 이해한다

최근 24시간의 뉴스와 경제 일정을 시장 데이터와 함께 Codex에 전달한다. Codex는 사실, 출처의 주장, 모델의 해석을 구분해 모닝 리포트를 작성한다.

### Act — 오늘의 확인 조건을 정한다

매수·매도 명령을 내리는 대신 오늘 주시할 위험, 관심 종목에 미칠 영향, 판단이 바뀌는 조건을 제시한다.

## 3. 기획이 발전한 과정

| 단계 | 질문 | 결정 |
|---|---|---|
| 1 | 어떤 제품인가? | 시장 대시보드와 종목 리포트를 연결하는 개인 금융 데스크 |
| 2 | 누가 쓰는가? | 우선 소유자 혼자 사용 |

| 5 | 데이터 속도는? | 가능한 최신값을 사용하되 15분 수준을 목표로 하고 기준 시각 공개 |

| 11 | 어떤 모습인가? | 카드형 AI 대시보드를 버리고 연속된 정보 표면의 Signal Desk 채택 |

## 4. Signal Desk

초기 시안은 둥근 카드, 균등한 타일, 장식용 그래프가 많아 전형적인 “AI가 만든 대시보드”처럼 보였다. 여러 레이아웃을 비교한 뒤, 정보 구조는 유지하면서 시각 언어를 완전히 다시 잡았다.

### 디자인 원칙

- 카드 모음이 아닌 하나로 이어진 분석 표면
- 숫자 → 해석 → 신호 → 일정으로 이어지는 읽기 순서
- 왼쪽 주황색 레일과 확신도 바를 고유한 시각적 서명으로 사용
- 둥근 모서리, 과도한 그림자, 장식용 그라데이션 배제
- 잉크 블랙과 중성 회색 위에 시그널 오렌지 `#F59B00` 사용
- 수치는 고정폭 글꼴, 해설은 읽기 편한 산세리프 사용
- 색상뿐 아니라 부호와 텍스트로 상승·하락·데이터 상태 표현

### 화면 구성

```text
┌────────┬──────────────────────────────────────────────────────┐
│ M/B    │ MARKET TAPE · 기준 시각 · 로컬 에이전트 상태        │
│        ├─────────────────────────────┬────────────────────────┤
│ OVER   │ CODEX MORNING THESIS        │ MARKET PULSE           │
│ MACRO  │ 헤드라인 · 해설 · 확신도    │ 위험 점수 · 시장 체제  │
│ EQTY   ├──────────────────┬──────────┴────────────────────────┤
│ ARCH   │ CROSS-ASSET      │ SIGNAL MATRIX · WATCHLIST         │
│        │ PRESSURE         │ 경제 일정 · 오늘의 확인 조건     │
└────────┴──────────────────┴───────────────────────────────────┘
```

## 5. 동작 방식

```text
무료 시장 데이터 + 최근 24시간 뉴스 + 경제 일정
                         ↓
                 검증 및 중복 제거
                         ↓
              날짜별 입력 스냅샷 저장
                         ↓
               로컬 Codex 자동 분석
                         ↓
          구조화된 JSON + Markdown 리포트
                  ↙                  ↘
         Signal Desk 표시       Discord 전송
```

### 매일 아침의 실행 순서

1. Windows 작업 스케줄러가 평일 오전 7시 30분에 파이프라인을 시작한다.
2. 시장 시세, 미국 금리, 최근 24시간 뉴스를 수집한다.
3. 누락·지연·중복을 확인하고 입력 스냅샷을 보관한다.
4. Codex가 정해진 JSON Schema에 맞춰 리포트를 생성한다.
5. JSON과 Markdown을 날짜별로 저장한다.
6. Discord에 핵심 요약과 전체 Markdown 파일을 보낸다.
7. 대시보드는 마지막 성공 리포트와 현재 데이터 상태를 표시한다.

## 6. 리포트가 답해야 하는 것

Codex 리포트는 단순 뉴스 요약이 아니라 다음 질문에 답한다.

- 오늘의 시장 체제는 위험 선호인가, 위험 회피인가?
- 가장 중요한 자산 움직임은 무엇인가?
- 뉴스가 시장 움직임을 어떻게 설명하는가?
- 한국장 개장에 어떤 변수가 중요한가?
- 관심 종목은 어떤 영향을 받을 가능성이 있는가?
- 오늘 확인해야 할 경제 일정과 위험 조건은 무엇인가?
- 데이터가 부족하거나 오래된 부분은 어디인가?

### 생성 원칙

- 입력에 없는 숫자를 만들지 않는다.
- 사실, 출처의 주장, Codex의 해석을 구분한다.
- 핵심 설명에는 데이터 또는 기사 출처를 연결한다.
- 원인이 불확실하면 단정하지 않고 가능성으로 표현한다.
- 상충하는 출처가 있으면 양쪽을 함께 보여준다.
- 매수·매도 명령 대신 시나리오와 확인 조건을 제시한다.

## 8. 기술 구조

```text
Next.js + TypeScript + Tailwind CSS
├─ app/                  화면과 로컬 실행 API
├─ components/           Signal Desk 컴포넌트
├─ lib/market-data/      시장 데이터 어댑터와 정규화
├─ lib/news/             RSS·GDELT·중복 제거
├─ lib/report/           Codex 실행·스키마 검증·Markdown 변환
├─ lib/storage/          파일 기반 스냅샷과 리포트
├─ lib/notifications/    Discord 전송
└─ scripts/              파이프라인과 Windows 예약 작업
```

- 패키지 관리자: `pnpm`
- 런타임: Node.js 20 이상
- 저장 방식: Git에서 제외한 로컬 JSON·Markdown 파일
- AI 실행: 로컬 Codex CLI 비대화형 모드
- 자동화: Windows 작업 스케줄러
- 데이터베이스와 별도 서버는 사용하지 않음

## 9. 실패해도 거짓말하지 않는 시스템

금융 리포트에서 가장 중요한 것은 “항상 결과를 내는 것”보다 “상태를 정직하게 보여주는 것”이다.

- 각 수치에 출처, 기준 시각, `fresh`·`stale`·`missing` 상태를 붙인다.
- 데이터 소스가 실패하면 두 번 재시도한 뒤 마지막 정상값을 `stale`로 표시한다.
- 미국 지수, USD/KRW, 미국 10년물 중 두 개 이상이 없으면 정상 리포트를 만들지 않는다.
- 뉴스가 모두 실패하면 숫자 기반 리포트를 만들고 `NEWS DEGRADED`를 표시한다.
- Codex 결과가 형식에 맞지 않으면 한 번 교정하고, 다시 실패하면 이전 성공 리포트를 유지한다.
- Discord 실패는 리포트 생성 성공과 분리해 기록한다.

## 10. 비용 원칙

프로토타입의 목표는 **추가 비용 0원**이다.

- 로컬 PC에서 실행
- 기존 Codex 로그인 세션 사용
- 무료 데이터와 공개 RSS 사용
- 파일 기반 저장
- Discord 웹훅 사용
- 클라우드 호스팅과 OpenAI API 키 사용 안 함

대신 오전 7시 30분 자동 실행에는 PC가 켜져 있어야 한다. 제품 가치가 검증된 뒤에만 클라우드 운영과 유료 데이터 전환을 검토한다.

## 12. 완료 기준

- Signal Desk에서 마지막 시장 상태와 리포트를 볼 수 있다.
- 한 번의 명령으로 수집 → 검증 → 생성 → 저장 → 알림이 완료된다.
- 실제 네트워크 없이도 샘플 데이터로 전체 파이프라인을 시험할 수 있다.
- Discord에서 요약을 읽고 전체 Markdown 리포트를 받을 수 있다.
- Windows 작업 스케줄러가 평일 오전 7시 30분 작업을 실행한다.
- 외부 소스가 일부 실패해도 상태를 명확히 표시하고 이전 성공 결과를 보존한다.
- 비밀값과 로컬 데이터가 Git에 들어가지 않는다.

## 15. 발표 구성 예시

10분 내외 발표라면 다음 순서로 사용할 수 있다.

1. **문제** — 정보는 많지만 나에게 필요한 아침 해석은 없다.
2. **해결책** — 한국 투자자를 위한 개인용 Codex 모닝 데스크.
3. **사용 경험** — Observe, Understand, Act.
4. **Signal Desk** — AI 대시보드 느낌을 걷어낸 실무용 정보 표면.
5. **작동 방식** — 무료 데이터 → Codex → 대시보드·Discord.
6. **신뢰 설계** — 출처, 기준 시각, degraded 상태, 실패 시 이전 결과 보존.
7. **비용과 범위** — 추가 비용 없이 로컬에서 먼저 검증.
8. **로드맵** — 데이터 파이프라인부터 자동화까지 단계적으로 구현.
